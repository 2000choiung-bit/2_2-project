# 📝 [Troubleshooting] DB 파트의 파편화된 테스트 스크립트 커밋으로 인한 루트 오염 방지 및 워크플로우 정립

## 1. 개요 (Overview)
* **문제 상황**: DB 담당자가 통합 연동 테스트를 위해 프로젝트 최상위 루트에 임시 Node.js 스크립트 및 SQL 덤프 파일들을 무분별하게 업로드하여 저장소 구조가 훼손됨.
* **해결 방안**: DB 담당 전용 역량 가이드라인 제공, `database/` 폴더 내 SQL 스크립트 관리 단일화, DB 전용 AI 프롬프트 가이드 배포.

---

## 2. 발생한 문제 및 해결 과정 (Trouble Shooting)

🔴 **문제: DB 담당자의 임시 연동 스크립트 및 SQL 파일 최상위 커밋으로 인한 프로젝트 오염**

* **원인**: DB 담당자가 연동 테스트를 위해 개별 테스트용 JS 코드(`test-login.js` 등)와 SQL 파일(`AIP.sql`)을 루트 경로에서 실행 및 커밋하여 Monorepo 구조가 깨짐.
* **해결**: 
  1. DB 담당자의 역할 범위를 `database/` 폴더 내 스키마(`init.sql`) 및 더미 데이터(`seed_data.sql`) 관리로 명확히 제한.
  2. 연동 테스트 방식 일원화: 백엔드가 제공하는 Swagger UI 및 Postman을 통해서만 테스트하도록 통합 연동 프로세스 재정립.
  3. DB 파트 전용 AI 프롬프트 지침을 전달하여 잘못된 파일 생성을 사전 차단.
* **느낀점**: 팀 프로젝트에서는 각 역할자의 '테스트 방식'까지 프로세스로 규정해 두지 않으면 저장소가 쉽게 오염될 수 있음을 깨달았다. 백엔드 개발자로서 전체 개발 생산성을 지키기 위해 파트별 작업 범위와 연동 접점(Swagger UI)을 명확히 제공해 주는 가이드의 중요성을 체득했다.
