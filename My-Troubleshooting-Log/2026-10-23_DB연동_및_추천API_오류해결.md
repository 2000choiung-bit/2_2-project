📝 [TroubleShooting] 백엔드 DB 연동 및 사이즈 추천 API 구축 과정 기록
1. 개요 (Overview)
작업 내용: 유저 신체 스펙과 상품 치수 데이터를 비교하여 최적 사이즈를 산출하는 추천 API 개발 및 DB 연동

관련 기술: Spring Boot, MySQL, JPA/Hibernate, Swagger UI

2. 발생한 문제 및 해결 과정 (Trouble Shooting)
🔴 문제 1: FK(외래키) 제약 조건으로 인한 테이블 생성 실패 (Error Code: 3734)
원인: SQL 덤프 파일 실행 시 users 테이블이 생성되기 전에 fitting_profiles 테이블 생성을 시도하거나, 연동 순서가 꼬여 참조 외래키인 user_id 컬럼을 찾지 못함.

해결:

테이블 생성 순서와 상관없이 실행 가능하도록 스크립트 상단과 하단에 SET FOREIGN_KEY_CHECKS = 0; 및 SET FOREIGN_KEY_CHECKS = 1; 구문을 추가하여 외래키 검사를 일시적으로 해제한 후 일괄 생성 완료.

🔴 문제 2: DB 파싱 및 쿼리 구문 오류 (Error Code: 1064)
원인: SQL 파일 내 주석 문구(-- MySQL dump...)와 쿼리가 줄바꿈 없이 붙어서 파싱 오류가 발생하거나 복사 과정에서 PRIMARY KEY 이하 구문이 누락됨.

해결:

SQL 스크립트 전반의 줄바꿈과 구문을 재정리하여 데이터 무결성을 갖춘 init.sql 표준 스크립트로 재구축.

🔴 문제 3: 추천 API 실행 시 500 Internal Server Error 발생
원인:

백엔드 추천 로직 계산에 필요한 유저 체형 데이터(member_profile)가 DB에 존재하지 않아 NullPointerException 발생.

application.properties의 DB 접속 URL이 실제 데이터가 들어있는 DB(virtual_fitting)가 아닌 기존 DB(virtual_fitting2)로 설정되어 데이터 조회가 실패함.

해결:

시연용 유저 스펙(키: 175cm, 몸무게: 70kg 등)을 member_profile 테이블에 추가하여 계산 입력값 확보.

application.properties의 spring.datasource.url 경로를 virtual_fitting으로 정상 수정 후 서버 재시작.

3. 최종 성과 및 결과 (Results)
Swagger UI 테스트 진행 결과 HTTP Status 200 OK 응답 수신.

productId=1, userId=1 입력 시 유저 스펙과 옷 치수를 비교하여 추천 사이즈(recommendedSize: "S"), 적합도 점수(fitScore: 72.5)가 정밀하게 계산되어 반환되는 것을 검증함.

프론트엔드 연동용 PR(Pull Request)에 API 엔드포인트 및 응답 명세서를 공유하여 협업 효율성 증대.
