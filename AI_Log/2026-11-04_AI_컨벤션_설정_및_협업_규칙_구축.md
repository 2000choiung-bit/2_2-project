# 🤖 [AI Collaboration Log] AI 개발 컨벤션 문서화를 통한 협업 생산성 및 코드 일관성 확보

## 1. 개요 & 목적
* **작업 목표**: 멀티 파트(FE/BE/DB) 프로젝트에서 AI를 코딩 파트너로 활용할 때 발생하는 코드 파편화(Style Mismatch) 및 구조 훼손을 방지하기 위한 표준 컨벤션(`AI_RULES.md`) 구축
* **사용한 AI 도구**: Gemini / ChatGPT
* **절감한 예상 시간**: 파트 간 연동 에러 수정 시간 (주당 약 6시간 이상 단축 예상)

---

## 2. 프롬프트 및 AI 제어 전략 (Prompt Engineering)

AI가 무작위로 코드를 생성하지 않도록 프로젝트 고유의 **기술 스택 constraint(제약 조건)**을 명시한 `AI_RULES.md` 제어 시스템 설계.

* **핵심 컨벤션 주입 내용**:
  1. **Spring Boot 3.x / Java 17 계층 구조 강제**: Controller - Service - Repository - DTO 분리
  2. **Swagger Annotation 의무화**: API 생성 시 자동 문서화 유지
  3. **주석 및 학습 포인트 추출 레벨 지정**: 단순 기능 완성이 아닌 코드 내 '핵심 백엔드 주석'과 'Trouble Shooting 노트' 자동 추출 가이드라인 제공

---

## 3. AI 제안 및 실제 적용 검증 (Code Quality Control)

* **문제 상황**: 단순 프롬프트 입력 시 AI가 Controller에 비즈니스 로직을 포함하거나 Entity를 직접 반환하려는 경향 발생.
* **개발자 직접 검증 및 교정**:
  - `AI_RULES.md` 내에 "Entity를 Controller 밖으로 직접 반환하지 않는다"라는 가이드라인을 명시하여 DTO 전환 패턴을 자동 유도.
  - 백엔드 개발자의 관점에서 AI가 작성한 코드의 트랜잭션 범위(`@Transactional`)와 데이터베이스 매핑 규칙(CamelCase to SnakeCase)을 2차 검증하는 검수 프로세스 수립.

---

## 4. 포트폴리오 어필 포인트 (Takeaway)

* **AI 도구에 대한 능동적 통제력**: AI를 단순 코드 생성기로 쓰는 것에 그치지 않고, 시스템 규칙(`AI_RULES.md`)을 수립하여 AI가 정해진 아키텍처 규격을 준수하도록 유도함.
* **학습 속도 및 생산성 극대화**: 개발 속도를 높이는 동시에 생성된 코드에 주석 및 백엔드 포인트를 남겨 **'AI 생성 코드의 100% 이해 및 검증'**이라는 기술적 주도권을 확보함.
