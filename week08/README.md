📝 [Study & Troubleshooting Log] 백엔드 리팩토링 및 DB 연동 전체 과정 정리
1. 프로젝트 초기 상태 (뼈대 구축)
기존에 백엔드 패키지 구조(Controller, Service, Repository, Entity/Domain 등)의 기본적인 도메인 뼈대 코드를 미리 작성해 둔 상태였음.

유저 스펙 데이터와 상품 데이터를 비교하여 최적의 옷 사이즈를 계산하는 추천 로직을 구현하고자 함.

2. DB 엔티티 설계 변경 및 도메인 구조 개편 (리팩토링)
문제 상황 (Cannot find... 에러 발생):
기존 코드에서는 Product 하나에 상품 기본정보와 상의/하의 상세 치수(가슴, 어깨, 총장 등)를 모두 집어넣으려고 했으나, 데이터 구조의 한계와 DB 스키마 변경으로 인해 참조 불가능 에러 발생.

구조 개편 (엔티티 분리):

Product (상품): 카테고리, 상품명, 가격, 상품 코드 등 공통 기본 정보만 관리하도록 역할 축소.

ProductSize (상품 상세 치수): 가슴둘레, 어깨너비, 총장 등 사이즈별 상세 치수 데이터를 저장하는 엔티티를 별도로 신설.

MemberProfile (유저 스펙): 유저의 키, 몸무게, 평소 착용 사이즈 등 체형 정보를 관리하는 엔티티/테이블 연동.

3. 코드 수정 및 규칙 재정의 과정
DB 구조가 Product 하나에서 Product + ProductSize + MemberProfile 구조로 분리됨에 따라 코드 전반의 수정 작업 진행:

클래스 및 메서드명 변경: 분리된 엔티티 역할에 맞게 Service, Repository, DTO의 클래스명과 메서드 호출부 수정.

의존성 및 패키지 정리: 엔티티 분리에 따른 import 구문 재정리 및 참조 관계 수정.

매핑 로직 수정: 유저 신체 스펙과 상품 치수를 1:1로 비교해서 fitScore와 recommendedSize를 산출하도록 비즈니스 로직 연동.

4. DB 연동 및 서버 실행 단계에서 발생한 트러블슈팅 (핵심!)
이 단계가 바로 질문하신 "4. DB 연동에서 정확히 한 일"입니다. 코드를 다 고쳤어도 실제 데이터베이스(MySQL)와 대화하는 과정에서 에러가 터졌고, 그걸 하나씩 잡은 과정입니다.

① SQL 덤프 파일 실행 및 외래키(FK) 제약조건 에러 (Error 3734)
상황: DB에 테이블을 만들고 초기 데이터를 넣기 위해 SQL 스크립트를 실행했으나 실패함.

원인: users 테이블이 만들어지기 전에 fitting_profiles 같은 참조 테이블을 먼저 만들려고 해서, 외래키(FK) 제약조건 오류 발생.

해결: 스크립트 상/하단에 SET FOREIGN_KEY_CHECKS = 0; / 1; 구문을 추가하여 외래키 검사를 잠시 끄고 일괄 생성 완료.

② DB 스크립트 파싱 구문 오류 (Error 1064)
상황: 복사/붙여넣기 과정에서 SQL 주석과 쿼리가 한 줄로 붙거나 구문이 일부 누락되어 문법 에러 발생.

해결: SQL 구문 줄바꿈과 제약조건 표준화를 거쳐 완전한 init.sql 파일로 재구성.

③ 백엔드 실행 시 500 Internal Server Error 발생 (두 가지 원인)
DB 주소 불일치:

원인: application.properties 파일의 설정이 데이터가 들어있는 DB(virtual_fitting)가 아닌 빈 DB(virtual_fitting2)로 설정되어 있어 조회 실패.

해결: 접속 URL 경로를 데이터가 존재하는 DB 주소로 정상 수정.

필수 입력 데이터 누락:

원인: 백엔드 알고리즘이 "1번 유저의 체형 정보"를 기반으로 계산을 시작해야 하는데, DB member_profile 테이블에 1번 유저 데이터가 없어서 NullPointer 에러 발생.

해결: 1번 유저의 키(175cm), 몸무게(70kg) 등의 테스트용 체형 데이터를 DB에 직접 넣어주어 계산 로직 정상 구동 성공.

5. 최종 결과 (Result)
Swagger UI를 통해 GET /api/recommendations/1?userId=1 테스트 실행.

서버에서 HTTP Status 200 OK 응답 수신.

productId=1 (티셔츠)에 대해 유저 스펙을 정밀 계산하여 recommendedSize: "S", fitScore: 72.5 데이터를 JSON으로 깔끔하게 반환하는 것을 최종 검증함.
